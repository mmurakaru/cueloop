Implementation Plan: Session Persistence

artifact plan.md author agent · codex-daemon base main @ 4a91c2e

§ Context

Review sessions currently live only in the daemon's memory. If the process crashes or is restarted mid-review, every pending annotation and the working verdict are lost, and the reviewer has to start the pass over. This plan persists each session to disk as it changes so a restarted daemon can recover the exact in-progress state.

1 Phase 1: Storage layer

Introduce a small append-friendly store that owns serialization of a session to disk. It writes atomically on every mutation and exposes a narrow interface the rest of the daemon can depend on.

  • server/storage/store.ts — the SessionStore class: load, save, list, delete.
  • server/storage/index.ts — public surface; constructs the default store from the data directory.
  • server/storage/schema.ts — the on-disk record shape and a schemaVersion guard.
interface SessionRecord { id: string; schemaVersion: string; artifact: Artifact; annotations: Annotation[]; verdict: Verdict | null; }

2 Phase 2: Recovery on boot

On startup the daemon scans the store, revives any session whose verdict is still null, and re-attaches its live socket so the reviewer's client reconnects seamlessly.

  1. Enumerate persisted records and filter to those without a final verdict.
  2. Rehydrate each into an in-memory session, validating schemaVersion and discarding records the current build can't read.
  3. Re-open the review channel and emit a resume event so connected clients repaint pending state.

? Open questions

  • Should we compact or garbage-collect sessions once a verdict is submitted, or keep them as an audit trail?
  • Is a single JSON file per session enough, or do we need a real embedded store once annotation volume grows?
