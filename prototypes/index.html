cueloop · review-surface concept gallery

Seven throwaway prototypes, one review loop: annotate a plan and a diff, then submit Comment / Approve / Request changes. Same content everywhere; each concept takes a different stance on layout and interaction. Judge them by keyboard feel — press ? inside any concept for its keybinding grammar.

  1. 01Manuscriptc · ⌘⏎ Zero chrome, document-first. UI appears only on demand; a floating pill carries the review.
  2. 02Margina · n/p Docs-style margin rail. Annotation cards live beside their spans; everything visible, spatial, calm.
  3. 03Terminalv · : · u A modal editor. NORMAL/VISUAL/EDIT modes, command line, status bar — vim grammar for review.
  4. 04Guided passn/p · x Review as a walkthrough. One unit spotlighted at a time; the pass ends at the verdict.
  5. 05Split stagee · s Editing is the review. Base left, working copy right, tracked changes live — the diff is the feedback.
  6. 06Command deck⌘k A command palette is the whole interface. Zero chrome until summoned; the palette teaches the fast path.
  7. 07BoardJ/K · v A review cockpit with a file tree. The plan is just another file; viewed-state tracks progress.
Shared grammar across all concepts: 1/2 switch plan/diff · c comment · e edit (tracked changes) · n/p pending items · ⌘z undo · ⌘⏎ finish review · ? cheat sheet. Pending feedback is invisible to the agent until one atomic submit.
