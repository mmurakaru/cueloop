## First run

Run `cueloop` with no arguments to open the inbox. The inbox lists every pending
review across all types - plans, working-tree diffs, and pull requests - so you
always land on the same place.

```bash
cueloop
```

From there, three verbs jump straight to the artifact you want:

```bash
cueloop plan          # open the latest pending plan
cueloop diff          # open the working-tree diff
cueloop review <pr>   # pull a pull request in and review it
```

Inside a review you read the artifact, annotate the exact lines that matter, and
send a verdict. The verdict is the structured result your agent waits on.

## Wire an agent

The point of cueloop is the gate between what an agent proposes and what it does.
For Claude Code or Codex, the plan gate opens a review and blocks on your
verdict before the agent starts to build. The agent stays paused until you
send a verdict, and it builds only when you approve.

See [Agent integration](/docs/agents/) for the exact hook setup.

That is the whole quickstart. cueloop reads an optional TOML config for
keybindings, the review surface, the theme, and Obsidian export, but every key
has a default - so you can start reviewing now and tune later.
