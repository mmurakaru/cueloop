cueloop maps one primitive onto each artifact type. The primitive tells cueloop what kind
of thing you want to review; it then picks the latest pending one of that type,
or the specific one you name.

```bash
cueloop                 # open the inbox across all types
cueloop plan            # latest pending plan review
cueloop reply           # latest pending reply review
cueloop diff            # latest pending diff review
cueloop prototype       # latest pending prototype review
cueloop review          # latest pending pull-request review
cueloop review 42       # pull PR 42 in and post the verdict back to it
```

## plan

`cueloop plan` opens the latest pending plan review. You can also address a
specific plan by its id or by its title, which is handy when several plans are in
flight at once.

## reply

`cueloop reply` opens the latest pending reply review. A reply is the agent's
previous message, submitted for review before you act on it. It is a markdown
artifact, so it renders and behaves exactly like a plan: you select spans,
comment, edit the wording directly, and cast a verdict that goes back to the
agent as structured feedback.

## diff

`cueloop diff` opens the latest pending diff review. With a dirty working tree and
no argument, it does one extra thing: it creates a review from the current
working tree instead of waiting for one to exist. So on a repo with uncommitted
changes, `cueloop diff` is the fastest way to put your own work in front of
yourself.

## prototype

`cueloop prototype` opens the latest pending prototype review. Give it an HTML
file and `cueloop prototype mockup.html` renders that mockup in the terminal and
creates a review of it: you click an element in the rendered page and anchor a
comment to it, the same way a plan anchors comments to sentences.

## review

`cueloop review` opens the latest pending pull-request review. Give it a PR and
`cueloop review <pr>` pulls that specific pull request in, lets you annotate it,
and posts the verdict back to the pull request itself.

## refine - the retrospective

The primitives above are forward-flow: they put one pending artifact in front of you.
`cueloop refine` looks backward. It reads the stored corpus of past reviews and
produces a markdown report of every reviewer annotation, grouped and attributed,
so the feedback that keeps recurring can be turned into concrete edits to how
your agent plans. See the
[Command reference](/docs/reference/commands/) for the flags.

## The inbox and `--latest`

Bare `cueloop` opens the inbox across all types, so you do not have to know which
primitive you want before you look. And on any primitive, `--latest` - alias `--open` -
always selects the latest review of that type.

```bash
cueloop plan --latest
cueloop diff --open
```
