The command tells cueloop what kind of work to open. Without an ID or title,
cueloop picks the latest pending Thread of that type.

```bash
cueloop                 # open the inbox across all types
cueloop plan            # latest pending plan review
cueloop reply           # latest pending reply review
cueloop diff            # latest pending diff review
cueloop prototype       # latest pending prototype review
cueloop review          # latest pending pull-request review
cueloop review 42       # review PR 42 and post the result
```

## plan

`cueloop plan` opens the latest pending plan review. You can also address a
specific plan by its id or by its title, which is handy when several plans are in
flight at once.

## reply

`cueloop reply` opens the latest pending reply review. A reply is the agent's
previous message, submitted for review before you act on it. It is a markdown
artifact, so it renders and behaves exactly like a plan: you select spans,
comment, edit the wording directly, and send a Message back to the agent.

## diff

`cueloop diff` opens the latest pending diff review. With a dirty working tree and
no argument, it does one extra thing: it creates a review from the current
working tree instead of waiting for one to exist. So on a repo with uncommitted
changes, `cueloop diff` is the fastest way to put your own work in front of
yourself.

## prototype

`cueloop prototype` opens the latest pending prototype review. Give it a Markdown
file and `cueloop prototype Combobox.md` creates a review of a component design doc:
the prop API, how it composes from existing primitives, and the callstack it fits
into. You anchor comments to its lines, the same way a plan anchors comments to
sentences. Reviewing a rendered pixel mockup instead is an opt-in experimental mode
(`[experimental] prototype_pixels`).

## review

`cueloop review` opens the latest pending pull-request review. Give it a PR and
`cueloop review <pr>` pulls that specific pull request in, lets you annotate it,
and posts the review back to the pull request itself.

## refine - the retrospective

`cueloop refine` reads past reviews and produces a Markdown report of reviewer
annotations. Use it to find feedback that keeps recurring. See the
[Command reference](/docs/reference/commands/) for the flags.

## The inbox and `--latest`

Bare `cueloop` opens the inbox across all types. On any review command,
`--latest` - alias `--open` - selects the latest review of that type.

```bash
cueloop plan --latest
cueloop diff --open
```

  <div class="callout__label">One primitive per type</div>
  plan, reply, diff, prototype, review. Each primitive owns one artifact type, defaults to the
  latest pending one, and takes an id or title when you need a specific one.
</div>
